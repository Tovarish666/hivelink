# hivelink

Управление фермой USB-модемов на Linux: десятки HiLink-стиков на одном хосте,
каждый со своей подсетью, маршрутизацией и присмотром.

Собран после разбора реальной аварии, в которой модемы отдавали 1.3 Мбит/с
вместо 50. Причина оказалась в драйвере ядра, а не в железе — фикс входит в
комплект.

---

## Что делает

| | |
|---|---|
| **Стабильные имена** | Номер модема привязан к физическому USB-порту навсегда. Новый модем не сдвигает раскладку соседей. |
| **Адресация и маршруты** | Модем N живёт в `192.168.N.0/24`, хост берёт `.100`, трафик уходит через персональную таблицу `policy routing`. |
| **Zero-CD** | Автоматический вывод из режима CD-ROM через `usb_modeswitch`. |
| **HiLink API** | Статус, включение передачи данных, переподключение, чтение SMS. |
| **Watchdog** | Проверки живости и лестница восстановления от переконфигурации до сброса USB. |
| **Защита резолвера** | Не даёт модему подсунуть свой DNS всему хосту. |
| **Фикс скорости** | Исправленный `rndis_host` через DKMS — пересобирается на каждое обновление ядра сам. |

Поддерживает любые USB-модемы, а не только Huawei: незнакомые устройства
опознаются по классам USB-интерфейсов, реестр дополняется в конфиге.

---

## Установка

```bash
git clone https://github.com/Tovarish666/hivelink && cd hivelink && bash install.sh
```

Если на хосте стоит другой стек управления модемами — снести его **до**
установки. Два стека одновременно будут драться за адресацию и маршруты.

### Сохранить существующую нумерацию

Если адреса модемов уже зашиты во внешние системы, закрепи их в
`/etc/hivelink/hivelink.conf` **до первого запуска**:

```sh
HL_SLOT_PIN="3-3:104 3-1.4.1.1:101"
```

USB-путь порта виден в `lsusb -t` и в `hivelink slots`. Привязка из конфига
имеет приоритет над автовыдачей и переживает потерю состояния и переезд
на другой хост. Без неё номера выдаются заново с `HL_SLOT_MIN`.

## Работа

```bash
hivelink status         # таблица модемов
hivelink doctor         # полная диагностика — начинай отсюда, если что-то не так
hivelink slots          # карта «USB-порт -> номер модема»
hivelink speed 101      # замер полосы и прироста ошибок приёма
hivelink info 101       # модель, прошивка, IMEI, сигнал
hivelink sms 101        # входящие SMS
hivelink reset 101      # сброс USB-устройства
hivelink rescan         # прогнать цикл прямо сейчас
```

Конфигурация — `/etc/hivelink/hivelink.conf`, все параметры с комментариями.

## Фикс скорости

### Симптом

Download ~1–2 Мбит/с при нормальном upload. Под Windows тот же модем на том же
порту выдаёт 50+. В счётчиках интерфейса почти весь приём — брак:

```
RX:  packets 20196   errors 17881
RX errors:  length 11084   crc 0   frame 6792   fifo 0   overrun 0
```

`crc=0` и `overrun=0` важны: данные по USB доезжают целыми и хост успевает их
забирать. Ломается разбор.

### Причина

`generic_rndis_bind()` сообщает устройству максимальный размер транзфера,
вычисляя его из `rx_urb_size`:

```c
dev->rx_urb_size = dev->hard_mtu + (dev->maxpacket + 1);
dev->rx_urb_size &= ~(dev->maxpacket - 1);
u.init->max_transfer_size = cpu_to_le32(dev->rx_urb_size);
```

Для High-Speed это `(1558 + 513) & ~511` = **2048 байт**. Модем честно уважает
это число и режет батчи так, что RNDIS-сообщения не помещаются в один URB.
А `rndis_rx_fixup()` собирать сообщение через границу URB не умеет — каждый
буфер разбирается отдельно, и у сообщения, начавшегося в предыдущем URB,
«заголовком» оказывается кусок полезных данных.

Видно при включённой отладке парсера:

```
bad rndis message 1/1460/36/1414, len 588
```

Заголовок корректен (`36 + 1414 + 8 ≤ 1460`), но пришло 588 байт из 1460.

Баг не специфичен для Huawei — та же сигнатура известна на Samsung Galaxy S8
([linux-usb](https://www.spinics.net/lists/linux-usb/msg165532.html),
[Debian #889831](https://www.mail-archive.com/debian-bugs-dist@lists.debian.org/msg1806154.html)),
открыт с 2018 и в апстриме не исправлен.

### Решение

Параметр модуля, переопределяющий `rx_urb_size` до того, как значение уйдёт
в `max_transfer_size`. Модем начинает укладывать батчи в наш буфер, парсер
перестаёт видеть обрывки.

```
было:  download 1.26 Мбит/с,  upload  8.69,  ошибок приёма ~85%
стало: download 46.58 Мбит/с, upload 43.66,  ошибок приёма ~0%
```

Оформлено DKMS-пакетом `hivelink-rndis`: `DEST_MODULE_LOCATION=/updates`
перекрывает штатный модуль, `AUTOINSTALL=yes` пересобирает его на обновлении
ядра. Размер буфера — `HL_RX_URB_SIZE` в конфиге, подбирается замером.

Failure mode безопасный: если конфиг потеряется, параметр станет `0` и драйвер
вернётся к штатному поведению — медленно, но рабоче.

### Ограничение

Исходник `rndis_host.c` берётся под текущее ядро. Если апстрим перепишет
`generic_rndis_bind()`, сборка упадёт с понятной ошибкой — патч тогда
переносится вручную, механика описана в `dkms/patch.py`.
После обновления ядра стоит заглянуть в `dkms status`; `hivelink doctor`
проверяет это сам и предупреждает, если загрузился штатный модуль.

## Что учтено из граблей

**Молчаливое отключение стадий.** В прошлом стеке отсутствие `usb_modeswitch`
приводило к `return 0` — целая стадия выключалась без единого сообщения и
маскировалась месяцами. Здесь `require()` либо валит цикл, либо громко ругается,
но никогда не делает вид, что всё хорошо.

**Одинаковый MAC.** Вся партия E3372 имеет один MAC, поэтому `enx<MAC>` даёт
всем модемам одно имя и раскладка зависит от того, кто поднялся первым. Имя
строится от номера слота, слот — от USB-пути. Плюс `arp_ignore=1` и
`arp_announce=2`, иначе ARP-ответы уезжают в чужую подсеть.

**Угон DNS.** Модем раздаёт себя как DNS-сервер. Адресация по умолчанию
статическая — DHCP-клиента нет, подсунуть нечего. Страж всё равно проверяет
резолвер каждый цикл: путей утечки много.

**Hotplug-шторм.** Когда партию втыкают целиком, udev выдаёт события пачкой.
Правило только дёргает systemd-юнит, а цикл идёт под общей блокировкой.

**USB autosuspend.** Гасится и правилом udev, и каждым циклом — иначе
случайные обрывы.

## Структура

```
lib/common.sh    конфиг, лог, блокировки, карта слотов
lib/usb.sh       обнаружение, Zero-CD, драйверы, сброс шины
lib/net.sh       адресация, policy routing, защита резолвера
lib/hilink.sh    клиент веб-API модема
lib/health.sh    проверки живости и лестница восстановления
sbin/hivelink-reconcile   один идемпотентный цикл
bin/hivelink              CLI
dkms/                     фикс rndis_host
```

## Требования

Debian 12+ / Proxmox VE 8+, `bash`, `usb-modeswitch`, `curl`, `iproute2`,
`dkms` и заголовки ядра для фикса.
